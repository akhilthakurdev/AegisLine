# Security policy

## Supported versions

The latest tagged release receives security fixes.

## Reporting a vulnerability

Do not open a public issue for an unpatched vulnerability. Until a dedicated security contact is configured, use GitHub's private vulnerability reporting feature on the published repository.

Include the affected version, component, prerequisites, impact, reproduction using inert test data, and any suggested mitigation. Do not include real credentials, personal data, or data obtained from systems you do not own.

## Scope

The activation script, hook configuration, plugin manifests, skills, and installation flow are in scope. Security disagreements about application code reviewed by an AI agent are not vulnerabilities in AegisLine unless the plugin deterministically introduces or conceals the issue.

AegisLine is guidance, not a scanner and not a security certification.
